# Diagnóstico – Assistente de Receitas puxa produtos errados/incompletos

**Job:** 3429e564-9805-4f12-9b3d-1432f5a4d961
**Data:** 2026-07-15
**Ambiente:** revski-main (https://revski-main.ddev.site:33177)
**Escopo pedido:** *"Não mexa em nada, só identifique a causa"* → **Nenhum código foi alterado.** Este é um relatório de causa-raiz.

---

## Sintoma relatado
Ao usar o Assistente de Receitas, o caso clínico identificado pelo cruzamento de parâmetros (Karnaugh) **não traz todos os produtos** – traz só alguns – e ainda **coloca produtos errados**. Começou **depois que os códigos de todos os produtos foram alterados**.

## Causa-raiz (confirmada)
**Divergência de códigos entre o oList/catálogo e a tabela Karnaugh.**
Os códigos de produto gravados na tabela Karnaugh (`tabela_karnaugh_produtos.produto_codigo`) continuam sendo os **códigos legados antigos** e **nunca foram re-sincronizados** com os novos códigos que os produtos passaram a ter após a reimportação do oList/Tiny. O assistente casa produto **por código exato**; como os códigos não batem mais, a maioria dos produtos não é encontrada e é descartada, e o *fallback* de busca aproximada pode anexar o produto errado.

### Como o assistente resolve os produtos (fluxo)
1. `AssistenteReceitaController@processar` gera o código do caso (ex.: `PSM1R1A1`) e chama `RegrasCondicionaisEngine`.
2. `TabelaKarnaugh::buscarProdutosPorCaso()` lê as linhas de `tabela_karnaugh_produtos` e devolve os `produto_codigo`.
3. `RegrasCondicionaisEngine::buscarProdutoPorCodigo()` procura o `Produto`:
   - 1º por **código exato** (`produtos.codigo = produto_codigo`);
   - 2º por **nome exato**;
   - 3º por **LIKE `%produto_codigo%`** em código OU nome (busca aproximada).
4. Em `processar()`, item com `produto_id === null` é **pulado** (`app/Http/Controllers/AssistenteReceitaController.php:247-249`) → some da receita.

### Por que "puxa só alguns"
O código exato não bate mais → produto não encontrado (`produto_id = null`) → item é descartado silenciosamente ao montar a receita.

### Por que "coloca coisas erradas"
Quando o código exato falha, o passo 3 cai no `LIKE '%código%'` e pega o **primeiro** produto cujo código/nome **contém** o fragmento. Quando o fragmento aparece em mais de um produto (ex.: `R0,0015H6` existe em *NOITE PESCOÇO R0,0015H6*, *R0,0015H6 NEODELINE* e *R0,0015H6-DYN3*), ele anexa um produto arbitrário/errado. É um risco de ambiguidade embutido no motor.

**4. Linha do tempo confirma a hipótese**
- `tabela_karnaugh_produtos`: criada 2026-03-26, **última atualização 2026-05-18**.
- `produtos`: criados/recodificados **2026-06-16**, atualizados até **2026-06-24**.
- Ou seja, os produtos foram recodificados **DEPOIS** da última carga das tabelas Karnaugh → os códigos do Karnaugh ficaram congelados no esquema antigo. Bate com o relato do usuário.

**5. O mapeamento existe, mas nunca foi aplicado ao Karnaugh**
- Existe o comando `karnaugh:atualizar-codigos` (`app/Console/Commands/AtualizarCodigosKarnaugh.php`) que substituiria os códigos, mas ele:
  - depende do CSV `docs/sanitization/mapeamento-karnaugh-olist.csv` que **não existe** no repositório;
  - além disso ele altera apenas os **XLSX** em disco, **não** a tabela `tabela_karnaugh_produtos` do banco (que é o que o assistente lê).
- O de‑para legado→catálogo existe apenas em documentação: `docs/sanitization/mapeamento-codigos-legado-base.md` (ex.: `DEMERANE-ULTRA-G30 → DEMERANE 30G`, `MAOS-DIA → DIA MAOS`, `HYDRAMINCE-DYNAMISEE-3 → DYNAMISEE 3`, `TONALITE-2-G30 → TONALITE 2 30G`, etc.). Esse mapa **não foi aplicado** aos registros do Karnaugh.

**6. Sem duplicidade de código nos produtos** (0 códigos duplicados) → o problema não é código repetido, é código **inexistente/desatualizado** no Karnaugh.

## Respostas às hipóteses levantadas no pedido
- **Verificar a Karnaugh** → a estrutura/casos estão ok; o que está errado são os `produto_codigo` desatualizados.
- **Verificar os parâmetros** → o cruzamento de parâmetros (`gerarCodigoKarnaugh` → `PSM1R1A1` etc.) está correto; o caso é localizado normalmente.
- **Produtos sincronizados com o oList** → os produtos ESTÃO no catálogo atualizado; quem ficou dessincronizado foi a **tabela Karnaugh**.
- **Divergência de códigos entre oList e Karnaugh** → **SIM, é exatamente esta a causa.**
