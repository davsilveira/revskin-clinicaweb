# Worklog — Título da aba do navegador: "Laravel Boilerplate" → "ClinicaWeb"

## Problema
Em várias páginas o título da aba do navegador aparecia como **"Laravel Boilerplate"**, o
nome padrão do boilerplate Laravel/Inertia. Deveria mostrar o nome do sistema: **ClinicaWeb**.

## Diagnóstico
O nome exibido vinha de três lugares, todos com o fallback padrão do boilerplate:

1. **Backend** — `config/app.php`: `env('APP_NAME', 'Laravel Boilerplate')`.
2. **Blade** — `resources/views/app.blade.php`: `<title inertia>{{ config('app.name', 'Laravel Boilerplate') }}</title>`.
3. **Frontend (Inertia/React)** — `resources/js/app.jsx`: `import.meta.env.VITE_APP_NAME || 'Laravel Boilerplate'`, usado no template de título `${title} - ${appName}`.

Quando `APP_NAME` não está definido no ambiente (caso de produção), esses fallbacks entravam
em ação e mostravam "Laravel Boilerplate".

Além disso, o nome do sistema estava grafado com **erro de digitação** em todo o projeto:
`ClincaWeb` (faltando o "i") — inclusive no `.env` (`APP_NAME="ClincaWeb"`), no texto da marca
no layout, nos logos (alt), nos rodapés dos PDFs e no conteúdo do manual. Por isso, mesmo onde
o nome aparecia, vinha errado. Corrigi para **ClinicaWeb**.

## Alterações

### Fallbacks do nome (Laravel Boilerplate → ClinicaWeb)
- `config/app.php` — fallback de `APP_NAME`.
- `resources/views/app.blade.php` — fallback do `<title>`.
- `resources/js/app.jsx` — fallback do `appName`.
- `scripts/start-dev.sh` — mensagem de inicialização.

### Correção do nome da marca (ClincaWeb → ClinicaWeb)
- `.env` e `.env.example` — `APP_NAME` (e, por herança, `VITE_APP_NAME` e `MAIL_FROM_NAME`).
- `resources/js/Layouts/DashboardLayout.jsx` — texto da marca e alt do logo.
- `resources/js/Pages/Welcome.jsx`, `resources/js/Pages/Auth/Login.jsx`,
  `resources/js/Pages/Auth/ForgotPassword.jsx`, `resources/js/Pages/Auth/ResetPassword.jsx` — alt dos logos.
- `resources/views/pdf/catalogo-produtos.blade.php`,
  `resources/views/pdf/relatorio-aquisicao-produtos.blade.php`,
  `resources/views/pdf/relatorio-receitas-medico.blade.php` — rodapés dos PDFs.
- `app/Manual/ManualContent.php` — menções à marca no manual.
- `routes/console.php` — comentário.
- `DEPLOY_HOSTINGER.md` — `APP_NAME` de exemplo do deploy (produção).

### Build
- `npm run build` (rodado no host — o `node_modules` do container não tem o binário arm64 do rollup).
  O bundle novo contém apenas `ClinicaWeb` e **nenhuma** ocorrência de "Laravel Boilerplate".
- `php artisan config:cache` regravado com o nome correto.

## Validação (backend + build)
- `config('app.name')` retorna `ClinicaWeb` (via `artisan tinker`).
- `curl https://revski-main.ddev.site:33177/` → `<title inertia>ClinicaWeb</title>`.
- `grep "Laravel Boilerplate" public/build/assets/app-*.js` → 0 ocorrências.

## Como validar manualmente
1. Acesse o site local: **https://revski-main.ddev.site:33177/** (ou produção após o deploy).
2. Faça login (usuário admin do ambiente).
3. Navegue por várias páginas (Dashboard, Receitas, Configurações, etc.) e observe o
   **título da aba do navegador** — deve mostrar `ClinicaWeb` (ou `<Página> - ClinicaWeb`),
   nunca mais "Laravel Boilerplate" nem "ClincaWeb".
4. Confira também o nome da marca no menu lateral (DashboardLayout) e os rodapés dos PDFs
   (catálogo de produtos, relatórios de receitas/aquisição).

## Deploy para produção
- Garantir que o `.env` de produção tenha `APP_NAME="ClinicaWeb"` (o `DEPLOY_HOSTINGER.md` já
  foi atualizado com esse valor).
- Rodar o build de assets em produção (`npm run build`) e limpar/recriar o cache de config
  (`php artisan config:cache`), pois `VITE_APP_NAME` é embutido no bundle em tempo de build.
