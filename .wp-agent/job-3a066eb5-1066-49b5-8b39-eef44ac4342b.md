## Situação em produção
O bug de troca de papel (médico → admin → médico) criou, ao voltar para médico, um
**médico NOVO e vazio** ligado ao usuário da Giovana, enquanto os pacientes (e as
receitas) dela ficaram presos no **médico ANTIGO**, agora **órfão** (sem usuário
vinculado). Por isso a médica não vê mais os pacientes: o app mostra só pacientes cujo
`paciente.medico_id === user.medico_id`.

O código já foi corrigido (não zera mais `medico_id`), mas isso previne novas ocorrências
— **não reconecta** os dados que já ficaram para trás em produção. Para isso criei um
comando de reparo rodável pós-deploy.

## O que criei
**`app/Console/Commands/ReestabelecerPacientesMedico.php`**
Comando Artisan `medicos:reestabelecer-pacientes`.

Estratégia: **mover** os pacientes/receitas/atendimentos do médico órfão (origem) para o
médico ao qual o usuário está **atualmente** vinculado (destino). Assim os pacientes
reaparecem **sem** mexer no login nem no perfil/CRM atual da médica.

Segurança:
- **Dry-run por padrão.** Só aplica com `--force`.
- Auto-detecta a origem por **CRM (dígitos)** entre médicos órfãos com pacientes; se
  houver ambiguidade ou nenhum, aborta pedindo `--origem=ID`.
- **Recusa** mover de um médico que ainda tenha usuário vinculado (não é órfão).
- Tudo dentro de uma transação. `--apagar-origem` (opcional) só remove o médico de origem
  se não sobrou nenhum registro apontando para ele.

### Assinatura
```
php artisan medicos:reestabelecer-pacientes {email}
      [--origem=ID]        # médico de origem; auto-detecta por CRM se omitido
      [--apagar-origem]    # remove o médico vazio de origem ao final (opcional)
      [--force]            # aplica de fato (sem isto, apenas simula)
```

## Como usar em PRODUÇÃO (passo a passo)
No servidor de produção, na raiz do projeto Laravel (após o deploy do código):

1. **Simular** (não altera nada) para conferir origem/destino e as contagens:
   ```
   php artisan medicos:reestabelecer-pacientes giovana.naccarato@revskin.com.br
   ```
   Confira: "Destino" = médico atual da médica; "Origem" = médico órfão com os pacientes;
   e o número de pacientes/receitas a mover. Se a auto-detecção reclamar de ambiguidade,
   descubra o ID do médico órfão e passe `--origem=ID`.

2. **Aplicar**:
   ```
   php artisan medicos:reestabelecer-pacientes giovana.naccarato@revskin.com.br --force
   ```
   (opcional, para apagar o médico vazio de origem: acrescente `--apagar-origem`).

3. **Validar**: logar como a Giovana e abrir **/pacientes** — os pacientes voltam a
   aparecer. O comando também imprime a contagem final de pacientes/receitas no destino.

> Dica: rode primeiro sempre sem `--force`. Se preferir manter histórico do médico antigo,
> **não** use `--apagar-origem` (ele fica apenas sem pacientes, inofensivo).

### Rodando via wp-agent/DDEV local (para testar antes)
```
cd "$(ddev describe revskin-main -j | jq -r .raw.approot)"
ddev exec php artisan medicos:reestabelecer-pacientes <email>          # simula
ddev exec php artisan medicos:reestabelecer-pacientes <email> --force  # aplica
```
No banco local a Giovana está **saudável** (médico 930, 53 pacientes), então o comando
responde "nada a fazer" — comportamento esperado.
