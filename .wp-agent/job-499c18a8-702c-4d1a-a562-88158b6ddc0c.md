# Job 499c18a8 — A numeração da receita conta as canceladas?

Só análise. **Nenhum código alterado.**

## Resposta: sim
`Receita::gerarNumero()` (`app/Models/Receita.php:228`) lê o `numero` de **todas** as receitas do paciente, sem filtrar status, pega o maior sufixo e soma 1. O resultado tem o formato `{paciente_id}-{000N}`.
- Cancelar não apaga a receita: só grava `status = cancelada` e `ativo = 0` (`ReceitaController::destroy`). O número dela continua ocupado.
- Por isso o número **nunca é reutilizado**. Se a 0002 foi cancelada, a próxima receita é a 0003.

Usado em: criação sem assistente, assistente (duas rotas), copiar, cancelar e duplicar, importações do legado.
`renumerarPorData()`, chamado só na fusão de pacientes e no import incremental, também inclui canceladas.

## Efeito junto com a mudança de ocultar canceladas
A lista padrão passa a ter **buracos** na sequência. Exemplo no paciente demo: aparecem Nº 1 e Nº 3, e a Nº 2 está cancelada.
No banco local, **15 pacientes** têm uma cancelada seguida de outra receita válida, ou seja, esse buraco já existe.

## Recomendação: manter como está
- O número vai impresso no PDF (`<title>Receita {{ numero }}</title>`) e segue para a integração com o Tiny/oList (`TinyPedidoSync`: `receita_numero`).
- Reaproveitar ou renumerar faria dois documentos diferentes terem o mesmo número. Uma receita já impressa ou já enviada ao Tiny passaria a apontar para outra.
- O buraco é rastreável: a cancelada continua visível pelo filtro "Cancelada" ou pelo link "Mostrar canceladas".

Se o cliente quiser a sequência "sem buracos" só na tela, dá para exibir uma contagem visual separada do código, mas isso cria dois números para a mesma receita. Não recomendo.
