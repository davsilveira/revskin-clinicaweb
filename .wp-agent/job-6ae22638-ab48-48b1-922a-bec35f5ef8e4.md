# Worklog — Investigação de médicos/secretárias duplicados + limpeza no plano

## O que foi pedido
Investigar por que há cadastros de médicos (e "muitos secretários") duplicados,
provavelmente herança do script de importação legado (`@legado.revskin.com.br`), e
prever no plano de normalização uma rotina que identifique e remova os que parecem
erro de importação.

## Investigação (dados reais de `revski-main`, via artisan tinker)
Rodei consultas sobre `users`/`medicos`/`clinicas`. Achados:
- 184 usuários: 11 admin, 96 médico, 77 secretária; **41 e-mails `@legado`**.
- **14 médicos duplicados** = par **conta legado (segura o `medico_id`/dados)** +
  **shell `@revskin.com.br` "Dra. X" sem `medico_id`**. Mesma local-part de e-mail,
  mesmo nome (± "Dra."). **As 14 shells têm 0 dependências** (checado:
  `pacientes.created_by/updated_by`, `atendimentos_callcenter.usuario_id/alteracao`,
  `user_medico.user_id` = 0). São lixo de importação, seguras de remover.
- **27 contas legado sem par** (12 médico + 11 secretária + 4 admin) = em uso → não
  apagar.
- **11 secretárias genéricas** `Secretaria Administrativa 1..11` (uma por clínica) →
  revisão manual.
- 0 CRMs duplicados, 0 médicos vazios, 0 e-mails idênticos; ninguém é médico+secretária.
- `AuditMedicoLinks` existente funde duplicatas de `medicos`, mas **não cobre** este
  caso (duplicação na tabela `users`).

Causa: 1ª importação criou `@legado` + médico; 2ª rodada recriou "Dra. X" sem
reaproveitar → conta vazia duplicada. Faltou deduplicação.
