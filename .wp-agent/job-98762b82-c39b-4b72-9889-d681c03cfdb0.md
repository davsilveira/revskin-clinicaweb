# Worklog — Explicação do "wizard de 2 telas" do anexo

## Pedido
O cliente perguntou o que é o "wizard de 2 telas" que citei como incremento de UI
ainda pendente da Opção 2.

## Resposta (resumo)
O wizard vem do 1º anexo (spec do "Novo Paciente"). É o cadastro quebrado em 2 etapas:
- **Tela 1 — dados compartilhados** (nome, CPF, nascimento, telefones, e-mail,
  endereço), **sem** os 3 campos privados; se o CPF já existir, pré-preenche.
- **Tela 2 — dados privados do médico**, que aparece ao clicar Salvar: só
  **Indicado por / Nº Registro / Observações**, sempre **em branco** (não traz os do
  1º médico).

Motivos do cliente: (1) privacidade — o 2º médico não pode ver os campos privados do
1º; (2) forçar o preenchimento do "Indicado Por" (o mais importante) numa tela
dedicada.

Relação com o que já foi implementado: o **comportamento** já existe no backend (os 3
campos são por vínculo/pivot, vêm em branco para quem não tem vínculo; upsert por CPF
reaproveita o paciente; endpoint `pacientes.lookup` pronto). O wizard é **só UX** —
hoje os 3 campos ficam no rodapé do mesmo formulário; o anexo quer uma 2ª etapa
explícita e em branco. O outro item ("múltiplos médicos para admin") é exibir na lista
de Pacientes todos os vínculos, não só o médico de origem — também só exibição.

## Ação
Explicação entregue na resposta ao cliente. **Nenhum código alterado.** Perguntei se
ele quer que eu implemente o wizard + exibição multi-médico agora (local, sem deploy)
ou deixe como incremento futuro.
