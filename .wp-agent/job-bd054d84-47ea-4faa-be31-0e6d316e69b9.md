### 2) Workflow manual de reparo (novo)
Criei `.github/workflows/reestabelecer-pacientes.yml` (`workflow_dispatch`) que roda
`php artisan medicos:reestabelecer-pacientes` em produção via SSH (mesmos secrets do
deploy). Inputs: `email`, `origem`, `force` (default false), `apagar_origem`.
Disparado com `wp-agent gh workflow run reestabelecer-pacientes.yml -f ...`.

### 3) Dry-run em produção — diagnóstico
O 1º dry-run mostrou que a Giovana (user #274) estava ligada ao médico **#944**
(CRM 283163, **0 pacientes** — o médico vazio criado pelo bug), e a auto-detecção
por CRM não achou a origem. Melhorei o comando para imprimir um **diagnóstico
read-only**, que revelou:
- médico **#930** — nome_legado "Giovana Naccarato Ferreira de Camargo", CRM 283163,
  **53 pacientes / 67 receitas**, sem usuário principal → a origem real.

O #930 não era auto-detectado porque tinha uma linha remanescente na pivot
`user_medico` (vínculo secundário/gestão, e-mail de outro usuário). Ajustei a
lógica: **só o vínculo PRINCIPAL (`users.medico_id`) bloqueia**; a pivot é apenas
avisada. (Coberto por teste novo.)

### 4) Dry-run confirmando o plano
Após o ajuste, o dry-run mostrou o plano correto:
```
Destino: médico #944 (CRM 283163) — pacientes atuais: 0
Origem:  médico #930 (nome_legado: Giovana ...) → pacientes: 53 | receitas: 67
PLANO:   mover 53 paciente(s), 67 receita(s) do médico #930 → #944 (origem mantida)
```

### 5) Aplicação real (`--force`)
Rodei com `force=true` (mantendo a origem, **sem** `--apagar-origem`). Resultado:
```
Aplicado com sucesso.
Destino #944 agora tem 53 paciente(s) e 67 receita(s).
```

### 6) Verificação final

médico #930 | pacientes=0 receitas=0

## Como rodar o reparo de novo (outros médicos, se preciso)
GitHub → Actions → "Reestabelecer pacientes de médico (reparo)" → Run workflow,
informando o e-mail. Rode primeiro com `force` **desmarcado** (dry-run); confira o
plano/diagnóstico; depois marque `force`. Use `origem` só se a auto-detecção pedir.

Via CLI:
```
wp-agent gh workflow run reestabelecer-pacientes.yml -f email=<email> -f force=false
wp-agent gh workflow run reestabelecer-pacientes.yml -f email=<email> -f force=true
```
