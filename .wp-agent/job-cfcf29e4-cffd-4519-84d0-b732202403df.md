# Follow-up: o que a checagem oList consulta no cancelar

## Pergunta
No cancelar, faz request ao oList e consulta se o pedido está Concluído e Entregue?

## Resposta
Sim, há request ao oList — mas não só “Concluído” e “Entregue”.

Fluxo:
1. Se a receita (ou o atendimento call center) tem `tiny_pedido_id` e Tiny/oList está habilitado.
2. CWB chama `TinyErpClient::obterPedido(id)` (API Tiny já usada no projeto).
3. Lê o campo `situacao` do pedido.
4. **Bloqueia** o cancelamento se a situação for considerada “já faturada / avançada”, alinhada ao webhook Tiny:
   - strings: `faturado`, `enviado`, `entregue`, `pronto_envio`, `atendido`
   - códigos V3: `1`, `5`, `6`, `7`
5. Se não houver pedido vinculado, permite cancelar sem chamar o oList.
6. Se a API falhar, falha fechado (não permite cancelar) com mensagem de erro.

Não há match explícito pela palavra “Concluído”; no mapeamento local usamos rótulos como Faturado / Enviado / Entregue / Pronto para envio / Atendido. Se o oList devolver outro texto (ex. “Concluído”), hoje **não** entra nessa lista — vale alinhar se esse status existir no ambiente deles.
