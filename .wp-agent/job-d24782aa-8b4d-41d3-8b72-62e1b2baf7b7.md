# Job d24782aa — Quais status disparam o webhook Tiny?

## Resposta curta

**Do lado do Tiny:** o webhook `situacao_pedido` dispara em **qualquer** mudança de situação do pedido (não só “Concluído”/“Enviado”).

**Do lado do ClinicaWeb:** o endpoint recebe todos, mas **só age** em alguns códigos. **Enviado sim**; **Concluído não** está mapeado (a menos que o Tiny mande outro código, ex. `entregue` / `atendido`).

## Tiny (envio)

Doc API v2: “qualquer atualização na situação de pedidos”. Payload: `dados.situacao` (código) + `dados.descricaoSituacao` (rótulo).

## ClinicaWeb (ação ao receber)

| Situação (código) | Efeito |
|---|---|
| `aprovado`, `preparando_envio` | Merge itens/preços **sem** marcar vendido |
| `faturado`, `enviado`, `entregue`, `pronto_envio`, `atendido` (+ V3: 1,5,6,7) | Merge + marcar vendido / aquisição |
| `cancelado`, `cancelada`, `devolvido`, `devolvida` (+ V3: 2) | Cancela receita |
| Outros (ex. `aberto`, e **`concluido` se vier assim**) | Recebe e **ignora** (“nada a fazer”) |

- **Enviado** → `enviado` → **sim**, sync “finalizado” (itens verdes).
- **Concluído** → **não** há `concluido` no código; se a UI do Tiny mostrar “Concluído” mas enviar `entregue`/`atendido`/`faturado`, aí sim.

Arquivos: `ProcessWebhookTinyJob.php`, `TinyErpClient::SITUACOES_FATURADAS_STR` / `isSituacaoPedidoFaturada()`.

Nenhuma alteração de código neste job.
