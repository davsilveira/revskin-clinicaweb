# Follow-up: `/api/receitas/{id}/pode-cancelar` não é oList

## Pergunta
O endpoint `/api/receitas/{id}/pode-cancelar` existe no oList? Houve confusão de fluxo oList→CWB?

## Resposta
**Não.** Esse path é **só do ClinicaWeb** (Laravel/Inertia). Não existe no oList/Tiny e o oList **não** chama o ClinicaWeb nesse fluxo.

Fluxo real (CWB → oList):

1. Médico clica **Cancelar Receita** no front (`Form.jsx`).
2. Front chama `GET /api/receitas/{id}/pode-cancelar` no **ClinicaWeb**.
3. Controller `ReceitaController::podeCancelar` → `ReceitaOlistCancelabilidade::verificar`.
4. Se a receita tem `tiny_pedido_id`, o CWB consulta o oList via `TinyErpClient::obterPedido()` (API Tiny já usada no projeto: `pedido.obter` V2 / `GET pedidos/{id}` V3).
5. Classifica a situação (`isSituacaoPedidoFaturada`) e devolve JSON `{ allowed, reason, … }` ao browser.
6. Só então, se permitido, o front confirma e faz `DELETE /receitas/{id}` (também no CWB), que agenda o cancelamento no Tiny (`CancelarPedidoTinyJob`).

Resumo: endpoint novo no CWB como **proxy/checagem**; a integração com oList é a API de pedido que o sistema já usava — não um webhook nem endpoint “pode-cancelar” do oList.
